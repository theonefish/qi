# 分支叙事（BRANCH）设计稿

> 状态：已实施（2026-11-08，M1-M4 全部完成并联调）　｜　日期：2026-11-08
> 关联：`docs/API.md` §7 / §8；`sql/init.sql` 中 chapter_node / user_progress / behavior_event

## 1. 背景与已定决策

目标：云展馆章节浏览中，章内出现**按钮交互的分支抉择**，访客选择后走向不同的内容发展。

| 决策点 | 结论 |
| --- | --- |
| 交互形态 | A 抉择展开式：分支处停下出按钮，渲染所选路径，未选内容隐藏；支持重选与「浏览全部」 |
| 作用范围 | 章内分支、章末汇合，不跨章携带状态 |
| 是否强制选择 | 强制：不选择不继续渲染后续内容 |
| 嵌套 | 模型允许分支内再放分支；内容规范建议每章 1–2 个分支点、嵌套不超过一层（超出为软提示，不阻断） |
| 下一章入口 | 放在汇合后的收尾节点（收尾节点全局唯一，发布校验保证） |
| 后台编辑 | 图编排形式，独立成页（不内嵌在 ChapterEdit） |

## 2. 数据模型

### 2.1 chapter_node 扩展

```sql
ALTER TABLE chapter_node
    ADD COLUMN next_node_id BIGINT NULL COMMENT '显式流向覆盖；NULL=按 sortOrder 的下一个节点',
    ADD COLUMN flow_pos     VARCHAR(50) NULL COMMENT '图编排画布坐标（x,y）',
    ADD KEY idx_next (next_node_id);
```

`node_type` 增加第五类 **BRANCH（分支抉择）**：`content` 存分支引导文案（如「你想先去哪条路线？」），BRANCH 节点自身**不参与默认线性链渲染**（强制选择），其 `next_node_id` 恒为空。

### 2.2 新表 node_choice

```sql
CREATE TABLE node_choice (
    id             BIGINT      NOT NULL AUTO_INCREMENT,
    node_id        BIGINT      NOT NULL COMMENT '所属 BRANCH 节点',
    label          VARCHAR(50) NOT NULL COMMENT '按钮文案，如「去制胎坊」',
    target_node_id BIGINT      NOT NULL COMMENT '选中后到达的同章节点',
    sort_order     INT         NOT NULL DEFAULT 0 COMMENT '按钮排序',
    create_time    DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time    DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_node (node_id)
) ENGINE = InnoDB COMMENT = '分支抉择选项（BRANCH 节点的按钮）';
```

选项随 BRANCH 节点保存，语义与其余扩展数据**不同**：`choices=null` 保留现有选项、`choices=[]` 清空、非空整体替换（先删后插）。其余扩展数据（media 等）仍是无条件替换。这一差异是「ChapterEdit 表单」与「图编排页」两处编辑互不覆盖的关键——表单保存不传 choices，图编排页保存才传。

### 2.3 流向语义，以及为什么需要 next_node_id（关键修正）

**有效后继规则**：非 BRANCH 节点的下一步 = `next_node_id ?? sortOrder 上的下一个节点`；BRANCH 节点的下一步 = 访客所选 choice 的 `target_node_id`。

仅有「sortOrder 线性链 + choice 跳转」时，**两条并行分支段无法回汇**。反例：

```
sortOrder：1, 2, 3(BRANCH), 4, 5(A段), 6, 7(B段), 8(汇合), 9(收尾)
```

A 段最后一个节点 5 的默认后继是 sortOrder 上的 6 —— 串进了 B 段开头。线性序列装不下两条并行链，必须给「段尾 → 汇合点」一个显式出口。因此增加 `next_node_id` 覆盖：本例中 5→8、7→8 两条覆盖边即可完成回汇。

由此形成的全图边集合（发布校验与图编排都基于它）：

1. 默认边：sortOrder 相邻链（灰、自动、不可编辑）
2. 覆盖边：next_node_id（可拖拽改接/删除）
3. 选项边：choice.target_node_id（橙色虚线，label=按钮文案）

**汇合节点** = 入度 ≥ 2 的节点，前端与后台图编排均可现算，不新增字段。

### 3.3 发布校验规则（POST /publish 硬校验，文案即 400 返回）

| 规则 | 级别 |
| --- | --- |
| BRANCH 选项 ≥2、label 非空 | 阻断 |
| choice.target / next_node_id 必须为同章未删除节点，且 ≠ 自身 | 阻断 |
| 全图（默认边+覆盖边+选项边）无环 | 阻断 |
| 入口（sortOrder 最小节点）可达全部节点（无孤岛） | 阻断 |
| 全部节点可达收尾节点（无死路） | 阻断 |
| 收尾节点（无有效后继）唯一 | 阻断 |
| 每章 BRANCH 数量 > 2 | 软提示 |
| 沿选项边的分支嵌套深度 > 2 | 软提示 |
| BRANCH content 引导文案为空 | 软提示 |

软提示：发布接口返回的 PublishRecord 中以 warnings 形式带出（如该结构尚不存在，则先以日志/提示字段占位，不改发布主流程）。

## 4. 小程序端

### 4.1 返回结构扩展（§7.3）

GET /app/chapters/{id} 的 node 对象增加：`nextNodeId`（nullable）、`choices: [{id,label,targetNodeId}]`（仅 BRANCH）。**仍然全量下发**——「重选」和「浏览全部」需要未选分支的内容，前端本地裁剪渲染。

### 4.2 路径渲染算法

```
function activePath(entryId, chosen /* map: branchNodeId -> choiceId */):
  path = []
  cur = entryId                                  // 入口 = sortOrder 最小节点
  while cur != null:
    path.push(cur)
    node = nodeMap[cur]
    if node.nodeType == 'BRANCH':
      c = chosen[cur]
      if c == null: break                        // 强制选择：渲染到此为止，等待点击
      cur = nodeMap.choiceTarget[c]
    else:
      cur = node.nextNodeId ?? nextBySortOrder(cur)
  return path
```

- 「浏览全部」：在分支处不裁剪——未选项的目标子树（沿有效后继走到汇合/收尾为止）渲染为折叠的灰色摘要块「未选择的路线」，可展开
- 「重选」：回到指定分支点，清空其后已做的选择并重算路径

### 4.3 交互细节

- BRANCH 节点渲染为引导卡片：引导文案 + 按钮组（按 choice.sortOrder 排列）
- 选择后按钮组收起为「已选：XX · 重选」，路径下方继续渲染所选内容
- 到达收尾节点展示现有「完成本章」与「下一章」入口（章尾语义=收尾节点，主流程不变）
- 可选（待定项）：章首提供「连续阅读」开关，忽略分支全量渲染（无障碍/快速浏览兜底）

### 4.4 进度、断点续读与行为上报

- `user_progress` 增列：`choice_path VARCHAR(500) NULL`（JSON：`[{"n":3,"c":1}]`，BRANCH 节点→所选 choice），断点续读按 {last_node_id + choice_path} 恢复路径；未记录时按默认路径走
- 阅读进度百分比仍按滚动算（渲染集合变为活跃路径后逻辑自然成立）；「完成本章」按钮仍出现在章尾（收尾节点）
- `behavior_event.event_type` 新增 **choose_branch**：`node_id`=BRANCH 节点 id，`target_type`='choice'，`target_id`=choiceId（统计「哪条分支更受欢迎」）

## 5. 后台图编排页（新独立页面）

### 5.1 路由与入口

- 独立路由 `/chapters/:id/flow`；入口：章节列表行操作「分支编排」+ ChapterEdit 顶栏按钮
- ChapterEdit 节点列表中 BRANCH 节点不提供选项编辑入口（显示「选项在分支编排页维护」），避免两处编辑冲突；nextNodeId 也不在表单暴露

### 5.2 技术选型

**@vue-flow/core ^1.x**（推荐）：Vue3 原生、MIT、自定义节点/边、拖拽连线缩放开箱即用，与 Element Plus 并存无冲突。备选 AntV X6（能力更强但包体与集成成本高）、自研 SVG（完全可控但工作量不成比例）。

### 5.3 画布元素与交互

| 元素 | 设计 |
| --- | --- |
| 节点卡片 | 类型徽标 + 标题 + 序号；BRANCH 橙色描边 + 选项把手；入度≥2 显示「汇合」角标；收尾节点绿色「章尾」徽标 |

### 9.3 保存链路（ChapterNodeService）

`save()` 与 `validateRequest()` 的改动：

```java
// validateRequest 新增 BRANCH case + 通用流向校验
case "BRANCH" -> {
    List<NodeSaveRequest.ChoiceItem> cs = request.getChoices();
    if (cs == null) break;                       // null=保留，编辑表单场景
    // [] =清空、单选项 = 编排中间态，均放行；「≥2」只在发布校验强制（实施联调结论）
    Set<Long> targets = new HashSet<>();
    for (ChoiceItem c : cs) {
        if (!StringUtils.hasText(c.getLabel())) throw new BusinessException("选项按钮文案不能为空");
        ChapterNode t = nodeMapper.selectById(c.getTargetNodeId());
        if (t == null || !t.getChapterId().equals(chapterId))
            throw new BusinessException("选项目标节点不存在或不属于该章节");
        if (!targets.add(c.getTargetNodeId()))
            throw new BusinessException("多个选项不能指向同一目标（请合并选项）");
    }
}
// nextNodeId / flowPos 校验（所有类型）
if (request.getNextNodeId() != null) {
    ChapterNode t = nodeMapper.selectById(request.getNextNodeId());
    if (t == null || !t.getChapterId().equals(chapterId)
            || request.getNextNodeId().equals(request.getId()))
        throw new BusinessException("流向目标节点无效");
}
```

`validateForPublish` 算法（全部基于 effectiveNext + choice 边组成的边集）：

```
1. 引用合法性：choice.target / next_node_id ∈ 本章节节点集 且 ≠ 自身   → BusinessException
2. 每个 BRANCH：choices ≥ 2 且 label 非空                              → BusinessException
3. 无环：迭代式三色 DFS（0未访问/1在栈/2完成），遇 1 即回边
   → BusinessException「章节路径存在循环：节点《title》」
4. 无孤岛：入口 = sortOrder 最小节点；正向 BFS，未触达节点
   → BusinessException「节点《title》无法从章节开头到达」
5. 收尾唯一：无有效后继的节点数必须 = 1（BRANCH 有选项，恒非收尾）
   → BusinessException「章节收尾节点必须唯一，当前 n 个」
   （无环 + 单收尾 + 全可达 ⇒ 所有路径必然终止于收尾节点，无需再单验死路）
6. 软提示（log.warn，不阻断）：每章 BRANCH > 2；沿选项边可达的 BRANCH
   嵌套深度 > 2；BRANCH content 引导文案为空
```

## 10. 小程序实现细化（M3）—— chapter.vue

### 10.1 状态与路径计算

```js
const chosen = ref({});            // { branchNodeId: choiceId }
const showAll = ref(false);        // 「浏览全部」开关（node-nav 行尾）
const pathIds = ref(new Set());    // 当前活跃路径节点 id 集合（灰显判定用）

const sortedNodes = computed(() => nodes.value);            // 后端已按 sortOrder 排序
const nodeById = computed(() => Object.fromEntries(nodes.value.map(n => [n.id, n])));

function nextOf(n) {                                        // 有效后继
    if (n.nextNodeId != null) return n.nextNodeId;
    const i = sortedNodes.value.findIndex(x => x.id === n.id);
    return i >= 0 && i < sortedNodes.value.length - 1 ? sortedNodes.value[i + 1].id : null;
}

const activePath = computed(() => {                         // §4.2 算法
    const list = [];
    let cur = sortedNodes.value[0];
    while (cur) {
        list.push(cur);
        if (cur.nodeType === 'BRANCH') {
            const cid = chosen.value[cur.id];
            if (cid == null) break;                          // 强制选择：到此为止
            const c = (cur.choices || []).find(x => x.id === cid);
            cur = c ? nodeById.value[c.targetNodeId] : null;
        } else {
            cur = nodeById.value[nextOf(cur)];
        }
    }
    return list;
});

const visibleNodes = computed(() => {
    pathIds.value = new Set(activePath.value.map(n => n.id));
    return showAll.value ? sortedNodes.value : activePath.value;
});
```

灰显判定：`showAll` 时 `pathIds` 之外的节点加 `ghost` class（归属到哪个分支可不做，badge 统一「未选择的路线」；如需归属，从每个未选 choice 的 target 沿 nextOf 走到主路径节点为止，沿途打标——实现放 util，不影响主流程）。

### 10.2 模板改动

- 节点循环与 node-nav chips 都改为遍历 `visibleNodes`，索引徽标用 `visibleNodes` 序号
- 新增 BRANCH 渲染块（风格呼应 `.quote-card`：深底、金色 kicker）：

```html
<template v-else-if="n.nodeType === 'BRANCH'">
    <view class="branch-card">
        <text class="branch-kicker">MAKE A CHOICE</text>
        <text class="branch-title">{{ n.content || '请选择你想走的路线' }}</text>
        <view class="branch-btns" v-if="chosen[n.id] === undefined">
            <view class="branch-btn" v-for="c in n.choices" :key="c.id" @click="choose(n, c)">{{ c.label }}</view>
        </view>
        <view class="branch-chosen" v-else>
            <text>已选 · {{ chosenLabel(n) }}</text>
            <text class="branch-repick" @click="reselect(n)">重选</text>
        </view>
    </view>
</template>
```

- 灰显包装：`<view class="node-section" :class="{ ghost: showAll && !pathIds.has(n.id) }">` + badge
- 底部栏「章节结尾 ↓」：若当前路径停在分支点（未选择），改为「请先做出选择 ↑」并滚到该分支点

### 10.3 交互函数

```js
async function choose(n, c) {
    chosen.value = { ...chosen.value, [n.id]: c.id };
    report('choose_branch', { chapterId: cid, nodeId: n.id, targetType: 'choice', targetId: c.id });
    api.readPosition({ anonymousId: anonymousId(), chapterId: cid, nodeId: n.id,
                       choicePath: JSON.stringify(toChoicePath()) });
    await nextTick();
    measureSoon();                              // 渲染集合变了，重测高度与进度
}

function reselect(n) {                          // 清除该分支及之后所有分支的选择
    const kept = {};
    for (const [bid, cidv] of Object.entries(chosen.value)) {
        if (分支顺序早于 n) kept[bid] = cidv;     // 分支顺序按 activePath 出现序
    }
    chosen.value = kept;
    /* 同步 readPosition；await nextTick(); measureSoon(); */
}

function toChoicePath() {                       // [{"n":3,"c":1}]
    return Object.entries(chosen.value).map(([n, c]) => ({ n: Number(n), c: c }));
}
```

- 续读：`load()` 取 progressList 后，若 `self.choicePath` 存在 → `chosen.value` 还原再渲染；`tryResume()` 时 `resumeNodeId` 不在 `visibleNodes` 中则滚到第一个未选择的分支点
- `measure()` / `readPercent` / 上报逻辑零改动——渲染集合变化后 `measureSoon()` 重测即可自然生效

### 11.2 FlowEdit.vue 结构

```html
<el-card>
  <template #header>  <!-- 返回 | 章节标题 | 新增分支节点 | 校验问题(N) | 发布章节（复用发布弹窗） -->
```

**自定义节点 FlowNodeCard**：

- 展示：类型徽标（沿用 ChapterEdit 的四色约定 + BRANCH 橙色）、`sortOrder` 序号、标题、选项数
- Handle：左侧 1 个 target；右侧 source——非 BRANCH 1 个（覆盖边用），BRANCH 按 choice 各 1 个（`:id="'c' + choice.id"`），另有「新增选项」把手
- 角标：入度 ≥ 2「汇合」、无有效后继「章尾」

**抽屉 = 撰写台（本页的核心交互）**：

- 点卡片 → `el-drawer`（size 70%）内嵌 **NodeEditor 公共组件**——从 ChapterEdit 的内联节点编辑器**抽取**而来（`components/NodeEditor.vue`），含 RichEditor 富文本、素材引用、TIMELINE/QUOTE/PROCESS 扩展数据表单，行为与 ChapterEdit 完全一致
- 抽屉顶部为节点摘要条（类型徽标、sortOrder、入度/收尾角标）；BRANCH 节点在表单下方追加**选项编辑表**（label 文本 + 目标节点下拉（限同章）+ 排序 + 删除行）
- 保存走既有节点接口（BRANCH 按 §2.2 三态语义带 choices）；保存后画布卡片标题即时刷新
- 抽屉不做手机预览（宽度不够）；预览仍以 ChapterEdit 右栏为准

**边生成（只画有效流向）**：

```js
sorted.forEach((n, i) => {
  const to = n.nextNodeId ?? sorted[i + 1]?.id;
  if (to) edges.push({ id: 'e' + n.id, source: n.id, target: String(to),
    type: 'flow-edge', data: { kind: n.nextNodeId ? 'override' : 'default' } });
});
choices.forEach(c => edges.push({ id: 'c' + c.id, source: String(c.nodeId),
  sourceHandle: 'c' + c.id, target: String(c.targetNodeId),
  label: c.label, type: 'flow-edge', data: { kind: 'choice' } }));
```

`kind` 决定样式：default 灰实线 / override 蓝实线 / choice 橙虚线；自定义边组件尾部带 × 删除按钮（choice 边 → 从所属 BRANCH 的 choices 里移除后全量保存；override 边 → `flowApi.setNext(null)`；default 边不可删）。

**交互落点**：

| 操作 | 实现 |
| --- | --- |
| 拖动卡片 | `@node-drag-stop` 防抖 800ms → `flowApi.saveLayout([{nodeId, flowPos: \`${x},${y}\`}])` |
| BRANCH 把手连线 | `@connect` → `el-prompt` 输入按钮文案 → `updateChoices(branchId, [...old, {label, targetNodeId}])` |
| 非 BRANCH 把手连线 | `@connect` → `flowApi.setNext(nodeId, target)`（BRANCH 自身恒不走覆盖边，前端禁用其默认把手） |
| 新增节点 | 顶栏「新增节点」→ 选类型 → 抽屉 NodeEditor 空表单 → `chapterNodeApi.create` → 刷新画布（sortOrder 追加到末尾，画布落在自动布局位置） |
| 撰写内容 | 点卡片 → 抽屉 NodeEditor 直接撰写并保存（见「抽屉 = 撰写台」）；抽屉右上保留「在编辑页打开」可选入口，跳 ChapterEdit 定位（手机预览联动场景） |
| 抽屉保存选项 | 「保存」→ `updateChoices`：`chapterNodeApi.detail` 取全量 → 改 choices → `chapterNodeApi.update` 全量回传（choices 语义 null=保留 / []=清空，见 §2.2） |

### 11.6 风险控制：画布 spike、备选与降级

- **spike 已完成（2026-11-08，6/6 通过，Vue Flow 选型确认）**，页面 `views/SpikeFlow.vue` + `components/spike/`。三条实测集成规则，正式 FlowEdit 必须遵守：
  1. **自定义边的 SVG path 必须 `pointer-events: none`**——否则边路径会盖住出发把手堵死后续连线；删除交互走 EdgeLabelRenderer 内的 × 按钮
  2. **数据单向流**：父组件数组是唯一事实源，增删一律数组替换（`edges.value = [...]`）；禁用 store 的 addEdges/removeEdges——与 v-model 混用会回写竞态，新增边不渲染
  3. **`isValidConnection` 只放幂等结构校验**（自环/端点完整性）——它在属性同步时会被用来复验所有已有边，不合格的边被静默移除；「一选项一边」等语义校验放 `@connect` 处理器（仅拦新建）
- **备选 AntV X6**（仅 spike ≥2 项失败时启用）：画布层重写约 +1~1.5 天（卡片改 x6-vue-shape、把手改 ports、删边改自带 tools）；抽屉撰写台/NodeEditor/校验面板/接口层零影响，数据模型与后端与选型完全无关
- **结构树降级视图**（低成本加固，可与任一选型叠加）：缩进列表 + 行内下拉改目标，复用全部接口；平时作为画布右侧「大纲」面板，画布故障时独立可用，编排不停摆（~0.5 天）
